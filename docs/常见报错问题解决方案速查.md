# 常见报错问题解决方案速查

> 按出现频率从高到低排列，每条只给「现象 + 解决」，详细原理见各阶段开发文档。

---

## 1. 端口被占用 / WinError 10013

**现象**：启动后端报 `[Errno 10048]` 或 `[WinError 10013] 以一种访问权限不允许的方式做了一个访问套接字的尝试`，`netstat` 查不到占用进程。

**解决**：
```powershell
netstat -ano | findstr :18000                                 # 查到 PID 就结束对应进程
netsh interface ipv4 show excludedportrange protocol=tcp      # 18000 落在保留段 → 执行下面两条
net stop winnat   # 管理员 PowerShell
# 保持后端启动，启动成功后再执行 net start winnat
```
仍冲突时把后端换到其他高位端口（如 `--port 18010`），并同步前端代理配置。

> 本项目已统一使用高位端口（后端 18000、前端 13000、Nginx 18080/18443、MySQL 16666、Qdrant 16333/16334、Ollama 21434），用高位端口是为了预防端口占用问题，完整清单见根目录 `README.md` 3.4.4 节。

---

## 2. Docker Compose 命令漏加 `--env-file`

**现象**：容器显示 `unhealthy`，后端连不上 MySQL；终端出现 `WARN: The "XXX" variable is not set`。

**解决**：所有 `docker compose` 命令（含 `down`）都必须带参数，且路径相对项目根目录：
```bash
docker compose --env-file docker/env/.env.dev up -d
```

---

## 3. 中间件端口与 Windows 冲突（MySQL 16666 / Ollama 21434 / Qdrant 16333）

**现象**：`docker compose up` 报 `port is already allocated` 或绑定失败。

**解决**：项目宿主机端口统一使用高位端口——MySQL `16666`、Qdrant `16333`/`16334`、Ollama `21434`（容器内仍为 3306 / 6333·6334 / 11434）。若仍冲突，在 `docker/env/.env.dev` 中改 `MYSQL_HOST_PORT` / `QDRANT_HOST_PORT` / `QDRANT_GRPC_HOST_PORT` / `OLLAMA_PORT`，并确认本地直跑时 `OLLAMA_BASE_URL=http://localhost:21434`。后端/前端/Nginx 端口见根目录 `README.md` 3.4.4 节。

---

## 4. DashScope / 模型接口 401、403

**现象**：嵌入、精排、评测调用失败；日志出现 `401 Unauthorized`、`403 AccessDenied` 或 `output=None`。

**解决**：
- `401`：先检查 Key 本身；Windows 上**用户作用域残留的旧 `DASHSCOPE_API_KEY` 会覆盖 env 文件**，用 `setx` 清理或在新终端验证；
- `403`：多为余额不足或模型下线（`gte-rerank` v1 已下线，必须用 `gte-rerank-v2`）；充值/换模型后重跑；
- 精排失败会自动降级为 RRF 序，链路不中断，但评测结果等价于未开精排。

---

## 5. 前端请求返回 401（登录态失效）

**现象**：接口返回 `401`，响应体 `code=3001`，页面被跳回登录页。

**解决**：本地 JWT 已过期（默认 24 小时，勾选「记住我」为 7 天）或后端已更换 `SECRET_KEY`。重新登录即可；后端重启不会导致失效。开发期频繁遇到可在路由守卫中提前解析 `exp`。

---

## 6. PowerShell 启动脚本报解析错误

**现象**：`start-backend.ps1` 报中文乱码或语法错误；或脚本内相对路径找不到文件。

**解决**：脚本需保存为 **UTF-8 with BOM**；且必须在**项目根目录**执行 `.\scripts\start-backend.ps1`（脚本内路径相对根目录）。

---

## 7. 磁盘空间被 Docker / uv 缓存占满

**现象**：C 盘空间持续减少；删除容器数据后空间未释放。

**解决**：
```bash
uv cache clean                                   # 先停后端再清理
# Docker Desktop → Settings → Resources → 清理/压缩磁盘（WSL2 的 VHDX 不会自动收缩）
docker system prune -a                           # 确认无用的镜像与容器
```

---

## 8. 本地 Ollama 模式启动失败或首答极慢

**现象**：后端启动报 Pydantic 校验错误；或本地模式第一次回答等待很久。

**解决**：`keep_alive` 只接受**整数秒**（如 `1800`），写 `"60m"` 会直接崩溃；模型缺失时后端会自动拉取（qwen2.5:7b 约 4.7GB），耐心等待；本地模式 AI 问答接口超时已放宽到 5 分钟，若前端仍报超时，检查 axios 单接口 `timeout` 配置。

---

## 9. 上传文档后列表里没有 / 一直显示向量化中

**现象**：上传接口返回成功，但列表看不到该文件；或状态长期 `processing`。

**解决**：
- 列表没有 → 后端按**文件内容 MD5 去重**，内容相同的文件会被跳过，属正常行为；
- 一直 `processing` → 查看后端日志的向量化任务异常；失败会写 `failed` 并在 `vectorizeMessage` 记录原因；
- 预览为空 → pdf/docx/xlsx 等二进制格式只按 UTF-8 读取前 10000 字符，可能为空，完整内容请用下载接口。

---

## 10. 设置页保存检索参数后不生效

**现象**：保存成功但链路行为没变；或重启后配置回到旧值。

**解决**：
- 确认响应 `message` 是否为「检索链路已重建即时生效」，若为「重建失败…下次重启生效」需查后端日志中的建链异常；
- 只改分块参数（`chunking.*`）不会立即影响已有文档，需重新上传或执行 `python -m app.service.rag.rebuild --all`；
- 平铺字段与分组字段同时提交时**平铺优先**，`topK` 会同步写 `rerank.top_k`。

---

## 11. 修改 `retrieval_config.yml` 后注释丢失 / 配置项被写坏

**现象**：调用设置页保存接口后，`backend/app/config/retrieval_config.yml` 的注释全部消失、缩进变化。

**解决**：这是 `yaml.dump` 的固有行为（只保留数据不保留注释），属预期；需要注释版配置时从 git 还原后再手工合并，不要指望接口写回保留注释。

---

## 12. YAML 配置写了 `off` 却仍走查询优化分支

**现象**：`query_optimize.mode: off` 不生效，日志显示按 `multi_query` 执行。

**解决**：YAML 1.1 会把未加引号的 `off/no/on/yes` 解析为布尔值，必须写成 `mode: "off"`。此类错误不报错、只改变行为。

---

## 13. 评测跑批异常或耗时过长

**现象**：跑批中途报错退出；或 260 题跑 30 分钟以上。

**解决**：
- 重构后残留旧函数引用会直接 `NameError`，改动后**全文件重读**而非只看 diff；
- `multi_query` / `hyde` 每题多一次 LLM 调用，耗时约为基线的 3~4 倍，建议后台运行并轮询日志；
- 结束时 `Event loop is closed` 的 Traceback 是 aiomysql 析构噪音，退出码 0 即非致命；
- 跑批中断后可直接重跑，评测脚本幂等。

---

## 14. 单元测试报 `TypeError` / 属性不存在

**现象**：mock 异步函数后调用报 `TypeError`；`patch.object` 报 `does not have the attribute`。

**解决**：
- 异步函数必须用 `new_callable=AsyncMock`，普通 `MagicMock` 返回的不是 coroutine；
- 包 `__init__.py` re-export 同名单例会遮蔽子模块，`import a.b.c as x` 拿到的是对象而非模块，改用 `importlib.import_module("a.b.c")`；
- pydantic 模型（`BaseRetriever` / `BaseChatModel`）上挂普通属性会报错，非声明字段用 `PrivateAttr`；
- BM25 单测语料需带干扰文档，保证查询词 `df < N/2`，否则 IDF 非正、检索必空；
- Qdrant 相关用例已全部 mock，**无需启动容器**。

---

## 15. 会话历史文件损坏导致 JSONDecodeError

**现象**：进入某个会话或发送消息时报 `JSONDecodeError`。

**解决**：`backend/chat_history/` 下对应的历史文件为空或格式损坏。删除该会话的历史文件（或清空会话消息）后重试；必要时在读取处增加空文件校验与重置。

---

## 16. 切换嵌入模型后检索报维度不匹配

**现象**：换了 `TEXT_EMBEDDING_MODEL` 后写入或检索报维度错误。

**解决**：新模型向量维度不同，需删除旧 Qdrant collection 并重新入库全部文档（`python -m app.service.rag.rebuild --all`）；collection 不存在时系统会按新维度自动创建。

---

## 17. 开启查询优化后指标反而下降

**现象**：开启 `multi_query` / `hyde` 后评测指标下降，但检索并未报错。

**解决**：不是 bug。当前 68 份高度近似制度文档的语料下，多路改写会稀释精排排序信号，HyDE 的假设文档会漂移到「整簇」而非正确文档。默认保持 `mode="off"`，仅在语料异质化或真实脏查询场景下按需开启并重新评测。
