# 账号管理说明文档

> 适用版本：v2.1（账号管理重构后）
> 相关文档：[接口JSON契约文档.md](./接口JSON契约文档.md)、[README.md](../README.md)

本文说明宸甄 PrivRAG 的账号体系、管理员初始化、日常账号运维与常见问题。系统为**单租户**设计，不提供自助注册，所有普通账号由管理员创建。

---

## 1. 账号体系

### 1.1 角色与等级

| 角色 | 说明 | 账号来源 |
|---|---|---|
| `admin` 管理员 | 拥有全部权限，可进入「账号管理」 | 服务启动时按环境变量 `ADMIN1_*`~`ADMIN3_*` 初始化 |
| `user` 普通账号 | 按等级 L1/L2/L3 获得不同权限 | 管理员在「账号管理」页创建 |

普通账号等级（包含关系 L3 ⊃ L2 ⊃ L1）：

| 权限 | 管理员 | L1 | L2 | L3 |
|---|---|---|---|---|
| Bot 问答（`chat`） | ✓ | ✓ | ✓ | ✓ |
| 查看统计数据（`statistics`） | ✓ | ✓ | ✓ | ✓ |
| 查看/下载知识库文档（`knowledgeRead`） | ✓ | ✓ | ✓ | ✓ |
| 上传/删除文档（`knowledgeWrite`） | ✓ | ✗ | ✓ | ✓ |
| 修改 RAG 参数（`ragConfig`） | ✓ | ✗ | ✗ | ✓ |
| 账号管理（`accountManage`） | ✓ | ✗ | ✗ | ✗ |

> 权限判定唯一来源为 `backend/app/core/permissions.py`；所有受限接口均通过 `Depends(require_permission(...))` 在后端校验，前端隐藏按钮只是体验优化，不能作为安全边界。

### 1.2 账号命名规则

- 普通账号：`czzsk` + 6 位补零自增 ID，例如 `czzsk000003`
- 生成方式：同一事务内先插入取自增 ID，再把账号名写回该记录，避免并发重号
- ID 超过 6 位（`>999999`）时创建失败并返回错误码 `4006`

### 1.3 账号状态

| 状态 | 含义 |
|---|---|
| `active` | 正常，可登录 |
| `disabled` | 已禁用，无法登录；已签发 token 在下一次请求时立即失效 |
| 已软删除 | `deleted_at` 非空，等价于禁用且不在账号列表显示；历史文档/会话/消息保留 |

系统**不做物理删除**，也不会因删除账号而级联删除其业务数据。

## 2. 内置管理员初始化

### 2.1 配置方式

在 `docker/env/.env.dev`（或 `.env.prod`）中配置：

```ini
ADMIN1_USERNAME=admin
ADMIN1_PASSWORD=Czzsk@2026Admin

# 可选：第 2、3 个管理员，未配置则跳过
# ADMIN2_USERNAME=
# ADMIN2_PASSWORD=
# ADMIN3_USERNAME=
# ADMIN3_PASSWORD=
```

启动后端时（Docker 容器或本地脚本）会执行：

1. 检查 `username` 是否已存在；
2. 不存在 → 以 bcrypt 哈希写入密码，`role=admin`、`level=null`、`status=active`；
3. 已存在且是管理员 → 跳过，**不会覆盖已修改过的密码**；
4. 已存在但不是管理员 → 打印错误日志并跳过（**不会自动提权**，需人工处理同名普通账号）。

> 启动日志只记录「已创建/已存在」，不会打印明文密码。

### 2.2 忘记管理员密码

在宿主机（或容器内）执行重置脚本：

```bash
# 项目根目录
backend\.venv\Scripts\python.exe -m app.cli.reset_password --username admin

# 或进入 backend 目录
python -m app.cli.reset_password --username admin

# 指定密码（不推荐，会留在命令历史中）
python -m app.cli.reset_password --username admin --password NewAdminPass2026
```

脚本生成随机密码时**只打印一次**，请立即保存。生产环境请优先使用随机密码方式。

## 3. 登录与密码策略

- 登录字段：账号 + 密码（`username`），请求可携带 `remember`：`true` 有效期 7 天，`false` 1 天
- 密码强度：8–64 位，且同时包含字母和数字（管理员初始密码建议 ≥12 位）
- 失败锁定：连续失败 `LOGIN_MAX_FAILURES` 次（默认 5 次）后锁定 `LOGIN_LOCK_MINUTES` 分钟（默认 15 分钟），返回 `2005`
- 统一错误提示：账号不存在、密码错误、已禁用、已删除均返回 `2001「账号或密码错误」`，避免账号枚举
- 新建账号与重置密码后 `mustChangePassword=true`，前端登录后会提示先修改密码

修改自己的密码：登录后进入「系统设置 → 修改密码」，或调用 `POST /api/auth/change-password`。改密成功后需使用新密码重新登录。

## 4. 账号管理页操作

入口：管理员登录后，左侧菜单「账号管理」（`/admin/users`）。非管理员无该菜单，直接访问路由也会被拦回 Bot 问答页，后端接口同样返回 `403 / 3002`。

| 操作 | 说明 | 结果 |
|---|---|---|
| 新建账号 | 点击「新建账号」，无需填写任何字段 | 自动生成 `czzsk0000xx` 账号与随机初始密码，**密码弹窗仅显示一次** |
| 调整等级 | 表格内等级下拉选择 L1/L2/L3 | 立即生效，无需对方重新登录 |
| 启用/禁用 | 表格内状态开关 | 禁用后对方立即无法继续请求 |
| 重置密码 | 行内「重置密码」 | 生成随机临时密码，**仅显示一次**，并置为必须改密 |
| 删除账号 | 行内「删除」 | 软删除：禁用 + 记录删除时间，历史数据保留 |

保护规则：

- 不能操作自己的账号（`4005`）
- 不能修改/禁用/重置/删除内置管理员账号（`4005`）
- 已删除账号不再出现在列表中，也不能被再次操作（`4004`）

> 初始密码与临时密码均不落库（仅存 bcrypt 哈希）、不写日志，关闭弹窗后无法再次查看；如遗失只能再次重置。

## 5. 权限与接口对照

| 接口 | 所需权限 | 管理员 | L1 | L2 | L3 |
|---|---|---|---|---|---|
| `GET /api/chat/*`、`POST /api/chat/messages` | 登录即可 | ✓ | ✓ | ✓ | ✓ |
| `GET /api/statistics/*` | 登录即可 | ✓ | ✓ | ✓ | ✓ |
| `GET /api/documents`、预览、下载 | 登录即可 | ✓ | ✓ | ✓ | ✓ |
| `POST /api/documents/upload`、`DELETE /api/documents/{id}` | `knowledgeWrite` | ✓ | ✗ | ✓ | ✓ |
| `PUT /api/settings/rag-config` | `ragConfig` | ✓ | ✗ | ✗ | ✓ |
| `/api/admin/users*` | `accountManage` | ✓ | ✗ | ✗ | ✗ |

错误返回：

- 未登录 / token 失效 / 账号被禁用或删除 → HTTP 401，`code=3001`（前端清登录态跳登录页）
- 权限不足 → HTTP 403，`code=3002`（前端提示，不退出登录）

## 6. 数据库变更与回滚

账号管理重构涉及 `user` 表新增列与数据回填，使用幂等迁移脚本完成（不删表、不改已有字段类型）：

```bash
# 进入 backend 目录后执行
python -m app.cli.migrate_account_module --dry-run   # 仅打印将要执行的 SQL
python -m app.cli.migrate_account_module             # 正式执行（可重复执行）
```

迁移内容：

1. `phone` 放宽为可空（历史账号仍可用手机号登录）
2. 新增 `role`、`level`、`status`、`must_change_password`、`created_by`、`deleted_at`、`failed_attempts`、`locked_until`
3. `username` 增加唯一索引
4. 历史数据回填：`username = phone`（账号名迁移后可在账号管理中查看）、`role='user'`、`level=1`、`status='active'`

回滚：执行前请备份 `user` 表（`mysqldump`），如需回滚用备份恢复；新增列可保留（旧代码不读取），不建议删除。

## 7. 常见问题

**Q：启动后登录提示「账号或密码错误」？**
A：确认 `.env` 中 `ADMIN1_USERNAME` / `ADMIN1_PASSWORD` 已配置且 backend 容器已重启注入；若该账号之前已存在且密码被改过，env 中的密码不会覆盖，请用 `reset_password` 脚本重置。

**Q：新建账号的初始密码丢了怎么办？**
A：无法找回，只能在账号管理中「重置密码」生成新的临时密码。

**Q：账号被禁用后已登录的页面还能用吗？**
A：不能。下一次请求后端即返回 401/3001，前端自动清除登录态并跳转登录页。

**Q：删除账号后其上传的文档会消失吗？**
A：不会。软删除只影响登录与列表展示，文档、会话、消息等历史数据全部保留。

**Q：能否把普通账号提升为管理员？**
A：不能。管理员只能由环境变量初始化，账号管理页仅支持调整 L1–L3 等级，避免误操作扩大权限面。

**Q：修改 RAG 参数提示保存失败？**
A：Docker 部署下 `backend/app/config` 为只读挂载，写盘会失败（已知限制）。可改为可写挂载，或在镜像构建时使用可写目录后重启生效。
