# 账号管理模块重构执行文档

## 0. 结论摘要：项目事实

| 项目实际情况（已核实） | 本方案处理 |
|---|---|
| 用户表`username` 列存在但**全部为 NULL**；实际登录账号是 `phone`（`NOT NULL UNIQUE`） | 复用 `username` 作为唯一登录账号；历史账号回填 `username=phone` |
| 当前有注册入口：登录页双 Tab（登录/注册）+ `/api/auth/register`、`/api/auth/sms-code` | 按需求删除前后端注册相关代码 |
| 忘记密码只能重新注册。无任何找回/重置能力 | 新增管理员重置 + 命令行重置管理员密码 |
| 实际为 `docker/env/.env.dev`、`.env.prod` 及 `.example` 模板 | 新增管理员变量写进这两套 env（含模板） |
| RAG 参数配置：`backend/app/config/retrieval_config.yml`，`GET/PUT /api/settings/rag-config` 热更新；**容器内该目录只读挂载** | 保留存储方式；写接口加 L3/管理员鉴权；只读挂载限制写入已知限制 |
| 数据库迁移工具：无 Alembic；建表靠 `SQLModel.metadata.create_all`（不会给已有表加列） | 新增幂等迁移脚本（只 `ADD COLUMN` / 加索引 / 放宽 NOT NULL，**不改字段类型、不删表**） |
| 现网运行方式：当前 `mysql` / `qdrant` / `ollama` 三个容器在跑，backend/frontend 由本地脚本启动 | 冒烟验证走本地 `scripts/start-backend.ps1` + `npm run dev` |

**本次强约束（已遵守）**：不改字段类型、不删表、不物理删除用户、不引入多租户/复杂 RBAC/OAuth/LDAP。

### 1.4 认证方式（现状细节）

- `POST /api/auth/login`：`{phone, password, remember}` → 查 `user.phone` + bcrypt 校验 → 更新 `last_login` → 签发 JWT。
- JWT payload 仅 `{sub: user_id, exp}`；`remember=true` 7 天，否则 1 天；密钥 `SECRET_KEY` 环境变量，缺省为开发默认值。
- `backend/app/dependencies.py::get_current_user`：解析 Bearer token → `session.get(User, id)`，无用户即 401；**不检查账号状态**。
- 无登录失败次数限制、无账号锁定、无密码强度策略（注册/改密仅要求 ≥6 位）。
- 注册：`/api/auth/register`（验证码固定 `123456`）、`/api/auth/sms-code`。
- 个人信息：`PUT /api/auth/profile`（昵称/头像）；改密：`PUT /api/auth/password`。

## 2. 改造方案

### 2.1 角色与权限矩阵（后端为唯一判定源）

| 功能（权限标识） | L1 | L2 | L3 | admin |
|---|---|---|---|---|
| Bot 问答 `chat:use` | ✅ | ✅ | ✅ | ✅ |
| 数据统计 `statistics:read` | ✅ | ✅ | ✅ | ✅ |
| 知识库搜索/预览/下载 `knowledge:read` | ✅ | ✅ | ✅ | ✅ |
| 知识库上传/删除 `knowledge:write` | ❌ | ✅ | ✅ | ✅ |
| 设置：修改密码 `account:password` | ✅ | ✅ | ✅ | ✅ |
| 设置：RAG 参数读写 `settings:rag` | ❌ | ❌ | ✅ | ✅ |
| 账号管理 `account:manage` | ❌ | ❌ | ❌ | ✅ |

等级包含关系 L3 ⊃ L2 ⊃ L1；`admin` 不受 level 限制。等级变更**即时生效**（JWT 不携带 role/level，`get_current_user` 每次请求读库）。

后端内部权限标识与接口返回给前端的 `permissions` 键一一对应：`chat:use → chat`、`statistics:read → statistics`、`knowledge:read → knowledgeRead`、`knowledge:write → knowledgeWrite`、`settings:rag → ragConfig`、`account:manage → accountManage`（`account:password` 不对外暴露，所有登录用户可用）。

### 2.2 权限集中实现（不散落业务代码）

新增 `backend/app/core/permissions.py`：

- 权限常量：`CHAT_USE`、`STATISTICS_READ`、`KNOWLEDGE_READ`、`KNOWLEDGE_WRITE`、`ACCOUNT_PASSWORD`、`SETTINGS_RAG`、`ACCOUNT_MANAGE`。
- `permissions_for(role, level) -> dict[str, bool]`：矩阵唯一实现，供 `/auth/me`、登录响应以及后端依赖共同使用。
- `has_permission(user, perm) -> bool`。

`backend/app/dependencies.py` 新增：

- `require_permission(perm)`：依赖工厂，未登录 / token 失效 / **账号已禁用或软删 → 401 `3001`**（复用前端清登录态逻辑）；无权限 → 403 `3002`。
- `require_admin` = `require_permission(ACCOUNT_MANAGE)`。
- `get_current_user` 增加 `status != active` 校验（禁用账号的存量 token 立即失效）。

接口声明示例：`Depends(require_permission(KNOWLEDGE_WRITE))`、`Depends(require_permission(SETTINGS_RAG))`、`Depends(require_admin)`。`require_permission` 内部仍调用 `get_current_user`，不重复写鉴权逻辑。

### 2.3 登录与注册

- **删除** `POST /api/auth/register`、`POST /api/auth/sms-code`、`PUT /api/auth/profile`。
- **登录** `POST /api/auth/login`：请求体 `{username, password, remember}`。
  - 兼容处理：若只传了 `phone` 字段（旧调用方），按 `username` 处理（`username` 与历史 `phone` 值一致，属零成本兼容，不额外暴露接口）。
  - 校验顺序：账号存在 → 状态 `active` → 未锁定 → bcrypt 校验 → 重置失败计数 → 更新 `last_login` → 签发 JWT。
  - 账号不存在 / 密码错误 / 已禁用 **统一返回** `2001「账号或密码错误」`（不泄露账号是否存在）。
  - 锁定中返回 `2005「登录失败次数过多，请稍后再试」`（见 8. 已知限制）。
  - 失败计数：`failed_attempts + 1`，达到 `LOGIN_MAX_FAILURES`（默认 5）→ 写 `locked_until = now + LOGIN_LOCK_MINUTES`（默认 15 分钟）并清零计数；登录成功清零。
- **修改密码** `POST /api/auth/change-password`：`{oldPassword, newPassword, confirmPassword}`；新密码 8–64 位且同时含字母与数字；成功后 `must_change_password=false`；原 `PUT /api/auth/password` 移除（前端同步）。
- **当前用户** `GET /api/auth/me`：返回新用户对象（含 `role/level/status/mustChangePassword/permissions`）。
- 会话过期沿用 JWT `exp`（记住我 7 天 / 否则 1 天），不引入服务端会话。

### 2.4 管理员初始化（启动时）

- 配置来源：`docker/env/.env.dev` / `.env.prod` 中的 `ADMIN1_USERNAME`、`ADMIN1_PASSWORD`，可选 `ADMIN2_*`、`ADMIN3_*`。
- `main.py` 的 `lifespan` 在 `init_db()` 之后执行 `seed_admins(session)`：
  - 变量缺失 → 记录 WARN 并跳过（不阻塞既有环境启动），绝不打印密码。
  - 账号不存在 → 创建 `role=admin, level=NULL, status=active, must_change_password=false, created_by=NULL`，密码 bcrypt 哈希。
  - 账号已存在且 `role=admin` → **不覆盖密码**，记录 INFO（避免重启改密）。
  - 账号已存在但 `role=user` → 不自动提权，记录 ERROR 提示人工处理（防止配置写错把普通账号提成管理员）。
- 管理员账号名不受 `czzsk` 规则约束，直接使用配置值（建议 `admin`）；不可通过 UI 创建管理员或提权。
- 管理员密码重置：命令行脚本（不走 UI）：
  - 容器：`docker compose exec backend python -m app.cli.reset_password --username admin`
  - 本地：`uv run python -m app.cli.reset_password --username admin`
  - 不带 `--password` 时随机生成并**仅在终端打印一次**，同时置 `must_change_password=true`。

### 2.5 账号管理（仅 admin）

- 账号名规则：`czzsk` + 6 位左补零自增 id（`id=1 → czzsk000001`）。实现：同一事务内 `session.add(row)` → `await session.flush()` 拿到自增 id → `row.username = f"czzsk{id:06d}"` → `commit`（`username` 唯一索引保证不冲突；`id > 999999` 时返回 `4006`）。
- 初始密码：长度 16，字符集排除易混淆字符 `0 O 1 l I`，强制包含大写、小写、数字；只返回一次，后端仅存 bcrypt 哈希；不写日志。
- 新建账号字段：`role=user, level=1, status=active, must_change_password=true, created_by=当前管理员 id`。
- 列表：分页 + 关键字（账号名）+ 等级/状态筛选；默认排除 `deleted_at IS NOT NULL`；返回 `createdByName`（通过 `created_by` 反查账号名）。
- 修改：只能改 `role=user` 的 `level`（1/2/3）与 `status`（active/disabled）；禁止改自己、禁止改管理员。
- 禁用/启用：禁用后登录被拒（历史文档、会话、消息全部保留）。
- 重置密码：仅对 `role=user`；返回临时密码一次；`must_change_password=true`。
- 删除：软删 —— `status=disabled` + `deleted_at=now()`；列表不再显示；**禁止删除/禁用自己、禁止操作管理员、禁止禁用最后一个管理员**（矩阵下管理员不可禁用，仍做兜底校验）。
- 审计：新增 `audit_log` 表记录管理员操作（`actor_id / action / target_id / detail / created_at`），不做复杂审计系统。

### 2.6 前端改动

- 登录页：删除注册 Tab 与验证码逻辑，只保留账号密码登录（字段名改 `username`）。
- 登录态：`user` 对象改为新结构（`username/role/level/status/mustChangePassword/permissions`）；`utils/auth.js` 增加 `hasPermission(perm)`；`mustChangePassword=true` 时登录后弹一次性提示（引导去设置页改密，不强制拦截）。
- 侧边栏：`AppLayout.vue` 按 `permissions` 渲染；`account:manage` 为真才显示「账号管理」。

## 3. 数据库迁移方案

### 3.1 字段变更（只增列 / 加索引 / 放宽 NULL，不改类型、不删表）

`user` 表目标结构（新增列已标注）：

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | int | PK AUTO_INCREMENT | 不变 |
| `phone` | varchar(20) | **改为 NULL**（原 NOT NULL） | 历史字段保留；新账号为空 |
| `username` | varchar(50) | **新增唯一索引 `ux_user_username`** | 登录账号，创建后不可改 |
| `password_hash` | varchar(255) | NOT NULL | bcrypt |
| `full_name` / `avatar` | 原样 | 原样 | 保留列，功能下线 |
| `role` | varchar(10) | NOT NULL DEFAULT 'user' | `admin` / `user` |
| `level` | tinyint | NULL DEFAULT 1 | 1/2/3；admin 为 NULL |
| `status` | varchar(10) | NOT NULL DEFAULT 'active' | `active` / `disabled` |
| `must_change_password` | tinyint(1) | NOT NULL DEFAULT 0 | 首次/重置后为 1 |
| `created_by` | int | NULL | 创建人 `user.id`（管理员创建） |
| `created_at` | datetime | NOT NULL | 不变 |
| `last_login` | datetime | NULL | **复用**为「最后登录时间」 |
| `deleted_at` | datetime | NULL | 软删除时间 |
| `failed_attempts` | int | NOT NULL DEFAULT 0 | 连续登录失败次数 |
| `locked_until` | datetime | NULL | 锁定截止时间 |

新增表 `audit_log`（SQLModel 建表即可，无需迁移）：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | int PK | |
| `actor_id` | int NULL | 操作人 id |
| `action` | varchar(32) | `create_user` / `update_level` / `update_status` / `reset_password` / `delete_user` |
| `target_id` | int NULL | 被操作账号 id |
| `detail` | varchar(500) NULL | 变更摘要（不写明文密码） |
| `created_at` | datetime | 操作时间 |

### 3.2 等价 DDL（迁移脚本内部执行）

```sql
-- 1) 允许新账号不填手机号（类型不变，仅放宽约束）
ALTER TABLE `user` MODIFY COLUMN `phone` varchar(20) NULL;

-- 2) 新增列（已存在则跳过）
ALTER TABLE `user`
  ADD COLUMN `role` varchar(10) NOT NULL DEFAULT 'user',
  ADD COLUMN `level` tinyint NULL DEFAULT 1,
  ADD COLUMN `status` varchar(10) NOT NULL DEFAULT 'active',
  ADD COLUMN `must_change_password` tinyint(1) NOT NULL DEFAULT 0,
  ADD COLUMN `created_by` int NULL,
  ADD COLUMN `deleted_at` datetime NULL,
  ADD COLUMN `failed_attempts` int NOT NULL DEFAULT 0,
  ADD COLUMN `locked_until` datetime NULL;

-- 3) username 唯一索引（现有 2 行 username 均为 NULL，MySQL 唯一索引允许多个 NULL）
ALTER TABLE `user` ADD UNIQUE KEY `ux_user_username` (`username`);

-- 4) 历史数据回填
UPDATE `user` SET `username` = `phone` WHERE `username` IS NULL OR `username` = '';
UPDATE `user` SET `role` = 'user' WHERE `role` IS NULL OR `role` = '';
UPDATE `user` SET `level` = 1 WHERE `level` IS NULL;
UPDATE `user` SET `status` = 'active' WHERE `status` IS NULL OR `status` = '';
```

### 3.3 迁移脚本（可重复执行）

- 路径：`backend/app/cli/migrate_account_module.py`。
- 执行：
  - 本地：`uv run python -m app.cli.migrate_account_module`
  - 容器：`docker compose --env-file docker/env/.env.dev exec backend python -m app.cli.migrate_account_module`
- 幂等策略：每一步先查 `information_schema.COLUMNS / STATISTICS` 判断是否存在，再执行；回填 SQL 为自然幂等。重复执行只输出「已存在，跳过」。
- 不在 `init_db()` 中自动执行 DDL 变更（`create_all` 不会改已有表），迁移由脚本显式触发；`init_db()` 仅负责新表 `audit_log`。
- 脚本执行前自动打印当前 `user` 行数与表结构摘要；失败即回滚该语句并退出非 0。

### 3.4 数据迁移策略

- 现有 2 个账号 → `role=user, level=1, status=active`，`username=phone`（可用原手机号登录，登录框输入原手机号即可）。
- id=1 账号拥有全部 68 篇文档：迁移后为 L1，**不能上传/删除**（符合矩阵，但影响日常使用）。处理方式：管理员登录后在「账号管理」把它改为 L3（不自动提权，避免越权）。
- 内置管理员由启动时 env 创建，不参与历史数据迁移。
- 不物理删除任何行；`full_name` / `avatar` 数据保留。

### 3.5 备份与回滚

- 备份（迁移前必做）：
  ```bash
  docker exec privrag-mysql mysqldump -uprivrag -pprivrag_dev_123456 --single-transaction privrag_dev > backup_before_account_migration.sql
  ```
- 回滚（二选一）：
  1. **推荐**：恢复备份 `docker exec -i privrag-mysql mysql -uprivrag -p... privrag_dev < backup_before_account_migration.sql`。
  2. 结构回退（会丢弃新增列数据，仅在无数据写入时使用）：
     ```sql
     ALTER TABLE `user` DROP INDEX `ux_user_username`;
     ALTER TABLE `user`
       DROP COLUMN `locked_until`, DROP COLUMN `failed_attempts`, DROP COLUMN `deleted_at`,
       DROP COLUMN `created_by`, DROP COLUMN `must_change_password`, DROP COLUMN `status`,
       DROP COLUMN `level`, DROP COLUMN `role`;
     ALTER TABLE `user` MODIFY COLUMN `phone` varchar(20) NOT NULL;  -- 需先确保无 NULL
     DROP TABLE IF EXISTS `audit_log`;
     ```
- 代码回滚：本次改动集中在新增文件与少量路由/页面，按文件清单逐项 `git revert` 即可。

| code | HTTP | 含义 |

| 阶段 | 内容 | 验收点 | 依赖 | 风险 |
|---|---|---|---|---|
| 2.1 数据与认证底座 | 迁移脚本执行；`User` 模型加字段；`audit_log` 模型；密码策略/生成器；登录改造 + 失败锁定；`/auth/me` 新结构；`change-password`；启动 seed 管理员 | 迁移可重复执行；管理员可登录；禁用账号无法登录；原 2 个账号可用原手机号登录 | 3.4 备份完成 | 迁移失败 → 用备份回滚；`username` 唯一索引冲突 |

风险点汇总：

1. **契约破坏性变更**：登录字段 `phone→username`、用户对象字段替换、注册相关接口删除。前端同步修改并在契约文档「变更管理」中记录。
2. **SQLModel `create_all` 不加列**：忘记跑迁移会导致 500，故启动日志显式提示缺失列（阶段二在 `init_db` 后做一次轻量列检查并 WARN）。

4. **容器内 RAG 配置只读**：PUT 在容器化部署下会失败（既有问题），冒烟验证用本地后端。
5. **JWT 无服务端会话**：禁用账号依赖每次请求查库（已实现）；改密不撤销已签发 token（列入后续建议）。

## 8. 已知限制与后续建议

**已知限制**

1. 容器化部署下 `backend/app/config` 为只读挂载，`PUT /api/settings/rag-config` 写盘失败（既有问题，本次不修）；本地后端可正常保存。
2. JWT 无服务端会话：改密/重置密码不会立刻撤销已签发 token（禁用账号已通过每次请求查库即时拦截）。
3. 锁定提示 `2005` 会暴露「该账号存在且被锁定」（错误密码与不存在账号仍统一为 `2001`）；如安全要求更高，可统一为 `2001`。
4. 历史账号 id=1 迁移后为 L1，失去知识库写权限，需管理员手动提级。
5. 软删除行在列表中默认不可见，无「回收站/恢复」UI，恢复需改库。
6. 账号名依赖自增 id，id 超过 999999 后无法生成（返回 `4006`）。
7. 密码策略（8–64 位含字母数字）为本次新增，旧账号 6 位密码仍可登录，只在改密时校验新密码。
8. `full_name` / `avatar` 列保留但功能下线，历史数据不清理。

**后续建议（不在本次范围）**

1. 引入 `token_version`，在改密/禁用时自增并使旧 token 失效。
2. 迁移工具化（Alembic），替代手写幂等脚本。
3. 账号管理增加「导出/审计日志查看」页面。
4. 生产环境把 `SECRET_KEY`、管理员密码纳入密钥管理，禁止明文入库出仓。
5. 统一时间处理（当前为 naive datetime，依赖容器时区）。

1. 登录账号确认为 `username`（历史账号用原手机号字符串登录），确认可接受契约字段 `phone→username`。
2. 历史账号默认 `level=1`，确认不自动提权（需管理员手动把 id=1 调为 L3）。
3. 管理员数量固定支持 3 个（`ADMIN1..3_*`），确认足够。
4. 新建账号与重置密码均置 `must_change_password=true`，前端仅做「登录后提示」不做强制拦截，确认可接受。
5. `PUT /api/auth/profile`（昵称/头像）与注册相关接口直接删除，确认无外部调用方依赖。

确认后，阶段二将严格按第 5 章顺序实现，并在偏离时先更新本文档。
